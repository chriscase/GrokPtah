# GrokPtah capability matrix

This is the authoritative status table for GrokPtah capabilities. Other
documents describe *how* a surface works; they must not contradict this matrix.
The companion path to a trustworthy 100% claim is
[`ROADMAP_TO_100.md`](ROADMAP_TO_100.md). The Build-loop tool inventory is
[`TOOL_MATRIX.md`](TOOL_MATRIX.md); that file must not contradict these Computer
Use or Computer Run rows.

**Shipped means present on `origin/main`.** Draft
[PR #352](https://github.com/chriscase/GrokPtah/pull/352) and source drafts
[#343](https://github.com/chriscase/GrokPtah/pull/343)–[#351](https://github.com/chriscase/GrokPtah/pull/351)
are **Pending — not shipped**. Open GitHub issues remain **release gates**
even when substantial code already exists; an open issue is not “complete.”
Epic checkbox text on [#301](https://github.com/chriscase/GrokPtah/issues/301)
and [#267](https://github.com/chriscase/GrokPtah/issues/267) is stale relative
to child issue **state** — cite state, not the epic body.

No capability in this matrix is live-certified against Grok Build. Hermetic
and deterministic tests are not live certification. **This matrix does not
claim 100%.**

For the isolated-visual row, “no host supervisor” means no **dispatchable or qualified** host
supervisor. The candidate now contains a crate-private macOS packaged-supervisor source seam that
owns descriptors and lifecycle transitions, but it remains source-only and cannot mint visual
authority or substitute for the signed packaged-runtime campaign.

## Status vocabulary

Exactly one of the four status columns is the *shipped-on-main* claim for the
row. The other three are `—`. Pending draft-PR work is never marked Supported.

| Status | Meaning |
| --- | --- |
| **Supported** | Present on `origin/main` and usable on the documented path. Remaining open issues, if any, are listed as release gates — they do not retract the code. |
| **Experimental** | Present on `origin/main` with deterministic tests, but an open issue still owns packaged, hardware, soak, or live-certification proof. |
| **Planned** | Issue-tracked or present only on an open draft PR. Includes **Pending — not shipped** objects from PR #352 / #343–#351. Isolated visual Computer Use ([#288](https://github.com/chriscase/GrokPtah/issues/288)), the named provider-quota receipt, selected packaged-desktop UX ([#308](https://github.com/chriscase/GrokPtah/issues/308) core), the recurring expert UI/UX review cadence, and the enterprise gateway review lane are Planned **and mandatory 100% exits** — they must not be moved to Explicitly unsupported or descoped as a waiver. Independent long-running workers ([#305](https://github.com/chriscase/GrokPtah/issues/305) core) are Experimental on the first slice **and remain a mandatory 100% exit** — they must not be descoped. |
| **Explicitly unsupported** | Refused on the current contract. Not a hidden fallback. Raw **global** Computer Use injection may stay here. Isolated visual Computer Use may not. The #305 independent long-running agent outcome may not. The #308 Codex-class core desktop interface may not. Recurring expert UX cadence may not. The enterprise gateway review lane may not, if we claim the full product vision. Documented #305 / #308 non-goals may. |

## Distinctions that must not be collapsed

1. **Grok Build session/gateway routing is already Supported.** GrokPtah loads
   `~/.grok/auth.json`, refreshes OIDC, and sends cli-chat-proxy headers.
   Executable xAI credential order is `XAI_API_KEY`, OS keychain API key,
   `GROKPTAH_TOKEN_COMMAND`, then the Grok Build session (`auth_store.rs`
   `resolve_xai_credentials`). Compatible gateway requests still consume
   provider quota as a provider-side effect. That routing is **not** a named
   secret-free **provider-quota receipt** (mandatory 100% live-provider exit:
   campaign/credential/route-bound consumption **and** exhaustion/429). It is
   **not** a GrokPtah local host quota ledger (PR #352, pending). It is **not**
   Grok Build **account-balance synchronization** (not implemented, **not** a
   100% requirement). Routing is not **exact live certification**
   (`LiveCredentialAttestation.certification_ready` is a stricter,
   still-unproven campaign gate). Hermetic `http_429` /
   `rate-limit-backoff-recovery` are not the live receipt. A live report that
   says quota was “not observed” fails stage 2. See the Grok Build routing,
   quota, receipt, and 100% evidence rows.
2. **Current semantic Computer Use deliberately avoids raw global mouse injection.** `pointer_fallback` is false on the macOS backend; the release
   gate rejects pointer fallback before backend dispatch. **Foreground activation is not equivalent to non-disruptive isolated Computer Use.**
   `ActivateTarget` plus a frontmost/focused-window check is the current
   shipped slice. A stacked, uncertified candidate adds calibrated exact-field
   background text entry only; [#287](https://github.com/chriscase/GrokPtah/issues/287)
   remains Planned/open until every target/action disposition and packaged proof passes. **Isolated visual Computer Use
   ([#288](https://github.com/chriscase/GrokPtah/issues/288)) is a mandatory
   product exit**, never an unsupported alternative: agent-owned isolated
   surface/cursor; global pointer, keyboard, focus, clipboard, and unrelated
   apps unaffected; takeover out-of-band and preemptive. Raw global injection
   remains Explicitly unsupported.
3. **Shipped ManagerSupervisor is not hosted Grokbot certification.** Durable
   restart/recovery is not evidence-retention certification and is not an
   operations drill. Operator-equivalent remote bearers are not
   least-privilege authority.
4. **First-slice workloads and closed [#307](https://github.com/chriscase/GrokPtah/issues/307) are not the independent long-running worker 100% exit.** [#305](https://github.com/chriscase/GrokPtah/issues/305) remains **open**. That core product goal cannot be descoped or marked Explicitly unsupported. Documented #305 non-goals may stay unsupported.
5. **Phase 2 UX design artifacts are not packaged-desktop UX certification.** [#308](https://github.com/chriscase/GrokPtah/issues/308) remains **open**. The Codex-class core interface cannot be marked Explicitly unsupported; documented #308 non-goals may. A one-time audit or mockup is **not** the recurring expert UI/UX review cadence.
6. **Closed [#169](https://github.com/chriscase/GrokPtah/issues/169) compatible profiles are not an enterprise gateway review-lane certification.** Company-gateway quota is that provider’s quota; it is not Grok Build quota or a Grok Build account balance. Secretly routing to a stronger external model is not this product outcome.

**Grokbot** is product language in
[#301](https://github.com/chriscase/GrokPtah/issues/301) and
[`ADR-002-runtime-boundaries.md`](ADR-002-runtime-boundaries.md) for
always-available hosted agents. There is no shipped binary or product named
Grokbot on `origin/main`.
