# GrokPtah capability matrix

This is the authoritative status table for GrokPtah capabilities. Other
documents describe *how* a surface works; they must not contradict this matrix.
The companion path to a trustworthy 100% claim is
[`ROADMAP_TO_100.md`](ROADMAP_TO_100.md).

**Shipped means present on `origin/main`.** Draft
[PR #352](https://github.com/chriscase/GrokPtah/pull/352) and source drafts
[#343](https://github.com/chriscase/GrokPtah/pull/343)–[#351](https://github.com/chriscase/GrokPtah/pull/351)
are **Pending — not shipped**. Open GitHub issues remain **release gates**
even when substantial code already exists; an open issue is not “complete.”
Epic checkbox text on [#301](https://github.com/chriscase/GrokPtah/issues/301)
and [#267](https://github.com/chriscase/GrokPtah/issues/267) is stale relative
to child issue **state** — cite state, not the epic body.

No capability in this matrix is live-certified against Grok Build. Hermetic
and deterministic tests are not live certification.

## Status vocabulary

Exactly one of the four status columns is the *shipped-on-main* claim for the
row. The other three are `—`. Pending draft-PR work is never marked Supported.

| Status | Meaning |
| --- | --- |
| **Supported** | Present on `origin/main` and usable on the documented path. Remaining open issues, if any, are listed as release gates — they do not retract the code. |
| **Experimental** | Present on `origin/main` with deterministic tests, but an open issue still owns packaged, hardware, soak, or live-certification proof. |
| **Planned** | Issue-tracked or present only on an open draft PR. Includes **Pending — not shipped** objects from PR #352 / #343–#351. |
| **Explicitly unsupported** | Refused on the current contract. Not a hidden fallback. |

## Two distinctions that must not be collapsed

1. **Grok Build session/gateway routing is already Supported.** GrokPtah loads
   `~/.grok/auth.json`, refreshes OIDC, and sends cli-chat-proxy headers. That
   is not the same as **complete quota observability** (GrokPtah does not read
   or synchronize a Grok Build account balance) and is not the same as
   **exact live certification** (`LiveCredentialAttestation.certification_ready`
   is a stricter, still-unproven campaign gate). See rows 2, 3, and 15.
2. **Current semantic Computer Use deliberately avoids raw global mouse injection.** `pointer_fallback` is false on the macOS backend; the release
   gate rejects pointer fallback before backend dispatch. **Foreground activation is not equivalent to non-disruptive isolated Computer Use.**
   `ActivateTarget` plus a frontmost/focused-window check is the current
   slice; background-safe semantic ([#287](https://github.com/chriscase/GrokPtah/issues/287))
   and an isolated visual backend
   ([#288](https://github.com/chriscase/GrokPtah/issues/288)) are Planned.

**Grokbot** is product language in
[#301](https://github.com/chriscase/GrokPtah/issues/301) and
[`ADR-002-runtime-boundaries.md`](ADR-002-runtime-boundaries.md) for
always-available hosted agents. There is no shipped binary or product named
Grokbot on `origin/main`.
