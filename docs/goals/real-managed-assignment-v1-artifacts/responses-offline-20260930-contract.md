# Managed Responses contract and qualification boundary

Research date: 2026-09-30. This is an offline qualification, with zero additional live provider requests.

## Primary contract and applicability

The [xAI Responses REST reference](https://docs.x.ai/developers/rest-api-reference/inference/responses) specifies `POST /v1/responses` and describes `max_output_tokens` as the maximum generated response tokens: **“This includes both output and reasoning tokens.”** This is the normative pre-send output bound used here. A 1,024 value therefore reserves generated reasoning as well as visible output; reasoning effort, timeout, byte limits and post-response arithmetic are not substitutes. The POST example has input 131, output 624, reasoning 246 and total 755, consistent with reasoning inside output. The same reference includes an inconsistent legacy/additive example in its other rendering/GET material. Those shapes are not accepted. Unknown usage extensions also remain unsupported.

[Grok Build settings](https://docs.x.ai/build/settings) documents the Responses backend and model completion-limit configuration. [Enterprise network requirements](https://docs.x.ai/build/enterprise) identifies `cli-chat-proxy.grok.com` as the inference proxy and distinguishes the direct API-key host. The host selects only the official OIDC proxy for this production profile.

The [first-party sampler](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-sampler/src/client.rs) maps the model completion limit into Responses `max_output_tokens`, posts to the selected base's `responses` endpoint, and supplies the model-routing headers. This supports application of the Responses dialect contract to the proxy route. **That applicability is an inference from the documented API, documented inference proxy and first-party routing implementation; no separate proxy-specific cap statement or live proxy enforcement measurement was obtained.** Current source is corroboration only. Exact CLI 1.0.41 behavior is established by the SHA-verified binary captures and actual production-path loopback qualification, not by current-main source.

[Function calling](https://docs.x.ai/developers/tools/function-calling) describes client-executed calls and returning `function_call_output` items to the model. The relay admits only the pinned local file functions and their discovery wrappers, refuses provider/server tools, and validates complete streamed call arguments before delivering bytes to the child. [Tool usage details](https://docs.x.ai/developers/tools/tool-usage-details) distinguishes local function calls from provider tool authority. [Streaming examples](https://docs.x.ai/developers/tools/x-search) expose completed/incomplete terminal events and usage. Only `incomplete_details.reason=max_output_tokens` with a valid bounded receipt receives known token settlement; it revokes the capability and cannot produce a successful managed harvest or another send.

Public Markdown reference snapshot SHA-256 is recorded in the validation artifact. Documentation examples do not establish observed live proxy accounting, and no live Responses compatibility, final billing, or full live G4/G5/G8 completion is claimed.

## Host admission and accounting

Production fixes destination `https://cli-chat-proxy.grok.com/v1/responses`, OIDC authentication, model `grok-build-0.1`, backend Responses, `max_output_tokens=1024`, reasoning summary `concise`, encrypted reasoning inclusion, `store=false`, and local file-tool authority. The child receives only a revocable local capability. Cap omission/increase, legacy cap aliases, backend/model substitution, server tools and incompatible reasoning configuration are refused. The host supplies upstream authentication and model override; child headers cannot choose upstream authority. The pinned CLI's unsolicited local title-model request is rejected before admission and cannot reserve, consume or interrupt assignment authority.

Let I be provider input, O provider output, R the reasoning subset, C cached input and T total. Required relationships are `T=I+O`, `0<=R<=O`, `0<=C<=I`, and `O<=1024`, with checked arithmetic. R is retained for audit and never added again. Cache is a subset and never refunds budget. Provider cost ticks remain separate; absence is UNKNOWN, while explicit zero is known zero even though this CLI omits zero from projections.

Before each physical send, checked settled T plus the complete sealed text-only request byte count, plus any owned opaque-reasoning reuse allowance, plus 1,024 must fit 16,000. Reused encrypted reasoning must match a fingerprint previously returned and durably settled by this same lease; its extra input allowance is all prior generated output, independent of ciphertext size. Foreign, modified or duplicated references fail closed. The host refuses unknown/contradictory usage before the child can act on that response, retains bounded credential-safe observations, and does not restore authority. The existing abandonment, completed-forward ownership and restart guards apply to both dialects. No wire idempotency guarantee is claimed for the Responses server.

Legacy Chat Completions is retained with its existing fail-closed arithmetic. The historical additive receipt (3591+11+260=3862) is unchanged and is not reinterpreted through this Responses mapping.
